# Real Career Alpha Case Collection

This directory is the protocol for collecting **real, anonymized Career Alpha loops**.

The goal is not to collect success stories. The goal is to collect decision traces that can improve `/radar → /wedge → /build → /proof → /position → /interview → /offer`.

## What counts as a useful case

A case should include enough evidence to answer:

1. What was the starting profile and target role?
2. What trend or demand signal changed the user's direction?
3. Which wedge was selected, and what alternatives were rejected?
4. What proof was built or contributed?
5. Which claims became stronger, stayed weak, or were downgraded?
6. What did interviews / outreach / applications reveal?
7. Did the user KEEP, REFINE, or PIVOT the career hypothesis?

A rejection can be a high-value case. An offer is not required.

## Evidence policy

Every published case must separate:

- **VERIFIED** — directly supported by an artifact or external record;
- **SUPPORTED** — reasonable, but not fully verified;
- **SELF-REPORTED** — reported by the participant;
- **PLANNED** — future work, never written as completed.

Do not publish private recruiter names, personal email addresses, phone numbers, private company documents, unpublished compensation, or anything the participant did not authorize.

## Minimum anonymization

Replace or generalize where needed:

- real name → `Participant A`;
- company name → `AI Infra Startup`, `Systematic Fund`, etc.;
- exact location → region if necessary;
- sensitive metrics → ranges or qualitative result;
- private repository → artifact type and verification status.

Anonymization must not upgrade evidence. "Private repo verified by maintainer" is different from "public GitHub repo".

## Collection target

The repository should prioritize **10–20 diverse loops** before drawing broad conclusions.

Useful diversity dimensions:

- AI Engineering / Agent Systems
- AI Product
- Quant / systematic research
- Robotics / Physical AI
- student vs. career switcher vs. experienced hire
- no-experience → first proof
- proof-rich → positioning
- interview failure → evidence repair
- wedge pivot after weak market response

## How to submit

Use the repository's **Share your Career Alpha** issue template or copy [`template.md`](template.md).

Cases should be reviewed for:

- evidence integrity;
- ownership boundaries;
- privacy;
- useful market feedback;
- no hindsight rewriting.

A case is a learning artifact, not marketing copy.
