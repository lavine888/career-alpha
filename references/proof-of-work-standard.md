# Proof-of-Work Standard

用于 `/build` 判断一个职业项目是否足以形成可验证证据。

## Minimum viable proof

一个合格项目至少应回答：
1. 你解决了什么真实问题？
2. baseline 是什么？
3. 你做了什么关键选择？
4. 如何验证结果？
5. 哪里失败了？
6. 哪部分是你本人负责？

## Evidence stack

优先级从强到弱：

1. 第三方可访问的产品 / PR / deployment
2. 可复现实验与 benchmark
3. commit history / architecture / tests
4. demo video / screenshots
5. 文档与用户反馈
6. 仅自述

## Definition of Done template

```text
Problem:
Target user:
Career claim to prove:

Baseline:

Implementation:

Evaluation:

Artifacts:
- repository
- README
- demo
- benchmark / dataset
- failure cases

Result:

Ownership:

Known limitations:
```

## Scope discipline

Proof of Work 的目的不是做完整创业项目。优先用 2–7 天回答一个关键问题。

好的 scope：
- “比较 4 种 agent retry policy 在 50 个任务上的稳定性”

差的 scope：
- “做一个世界领先的通用 AI Agent 平台”

## Portfolio multiplier

优先选择一份工作能生成多种资产的项目：
- GitHub repo
- benchmark
- technical article
- demo
- resume bullet
- interview story
- social post

但任何二次内容都不能强于底层事实。
