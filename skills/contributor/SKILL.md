# /contributor — Verified Open-source Contribution

目标：用真实协作建立外部证据，不把“刷 PR 数量”当成目的。

## Workflow

1. 读取目标岗位、技术栈、`/wedge` 输出和每周可投入时间。
2. 优先筛选：
   - 与目标能力相关；
   - 仓库活跃；
   - issue / contribution guide 清晰；
   - 改动可以独立验证；
   - 有机会形成面试可讲的技术判断。
3. 候选分两层：
   - Quick Wins：文档、测试、bugfix、小功能；
   - Signature Contribution：能体现系统理解的更深贡献。
4. 在任何写操作前先展示：仓库、问题、拟改动、验证方法和风险。
5. 用户确认后再执行 fork / branch / patch / PR 等动作。
6. 合并状态、链接、review 反馈、实际改动写入 Claim–Evidence Ledger。

## Integrity rules

- 未提交：写“planned”。
- 已提交未合并：写“PR open / collaboration in progress”。
- 已合并：才写“merged contribution”。
- 不把 typo 修复包装成核心系统架构贡献。
- 可以总结多个真实小贡献的共同能力，例如文档质量、DX、测试覆盖，但必须保留事实边界。

## Default output

### Contribution Candidates
| Repo | Issue/Area | Why it fits | Difficulty | Evidence value |

### Recommended Sequence
先做 1–2 个低摩擦贡献建立协作节奏，再做 1 个能深入展开的贡献。

### Evidence Capture
每个贡献记录：
- URL
- commit / PR
- changed files
- tests / validation
- review feedback
- ownership
- final status

## Handoff

完成后交给 `/proof` 建 Evidence Card，再由 `/position` 转成岗位语言。
