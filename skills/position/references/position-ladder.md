# Positioning Ladder

Career Alpha uses three levels of positioning so that stronger language never silently outruns the evidence.

## 1. Safe Position

Definition:

- directly supported by current `VERIFIED` / strong `SUPPORTED` claims;
- low risk under interview follow-up;
- no hidden upgrade of title, scale or ownership.

Example:

```text
AI / Agent Application Engineer with hands-on experience in evaluation and reliability tooling.
```

Use when the candidate has built and evaluated relevant systems but has not owned production infrastructure.

## 2. Strong Position

Definition:

- more differentiated market framing;
- still defensible if the candidate states context and boundary;
- may combine several evidence-backed claims into a stronger narrative.

Example:

```text
Agent Systems Engineer focused on evaluation, harness reliability and context strategy.
```

Boundary:

> Experience comes from self-directed benchmarks and project work, not from owning a large production platform.

## 3. Future Position

Definition:

- a strategically useful next identity;
- currently blocked by explicit evidence gaps;
- must never be written as current fact.

Example:

```text
Future position: Agent Infrastructure / Reliability Engineer
```

Evidence required:

- production observability;
- real workload scale;
- latency / cost ownership;
- external collaboration.

Future Position is a **build target**, not a resume headline.

---

# Choosing the level

Use the strongest level that survives these checks:

1. Can the candidate explain every noun?
2. Can the candidate point to evidence?
3. Does the title imply production / organization scale not actually owned?
4. Would a hiring manager feel misled after a five-minute technical follow-up?

If #4 is yes, downgrade.

---

# Positioning formula

A good one-line position usually combines:

```text
role family + differentiating capability + proof context
```

Examples:

```text
AI Product Engineer building agent workflows with evaluation-first engineering.
```

```text
Data / Quant Engineer with reproducible factor research and backtesting evidence.
```

Avoid identity soup:

```text
AI Engineer | PM | Quant | Growth | Founder | Researcher
```

The goal is fast comprehension, not listing every interest.

---

# Evidence-gap ladder

For each desired future position, map:

| Target capability | Current claim | Current confidence | Missing evidence | Best next action |
| --- | --- | --- | --- | --- |

Then route:

- self-build proof → `/build`;
- external collaboration → `/contributor`;
- fact uncertainty → `/proof`;
- knowledge weakness → `/interview` or learning plan.
